# 使用文档

MiraiAccount 是一套账号中心与单点登录平台：统一管理用户、作为 OAuth2/OIDC 授权服务器，并内置管理后台。本文按使用角色说明功能。

## 首次使用：开箱向导

站点尚未初始化时，首次访问会进入开箱向导。向导分为三个阶段，需逐步满足前置条件：

1. **数据库连接**：填写主机、端口、账号、密码与库名。应用在创建超管时会自动建库建表，因此此处账号需具备建库权限。
2. **创建超级管理员**：设定全局最高权限账号的用户名与密码。用户名不能用保留字 `admin` / `superadmin`，仅支持 4–16 位字母数字或下划线。创建成功后系统会以该账号自动登录。
3. **站点配置**：填写站点标题与对外访问地址。站点 URL 会在授权链接、邮件与 WebAuthn 中作为基准地址。

各步采用增量保存，已完成步骤带绿色对勾，可回看但不能跳过后面的依赖步骤。

## 面向用户

### 注册与登录

支持密码登录，开启后可叠加 TOTP 两步验证或 WebAuthn 无密码登录。注册时需邮箱，头像由邮箱哈希到 Cravatar 服务生成全局统一头像。

- **TOTP**：在两步验证中启停 TOTP。启用时需扫描二维码并完成一次验证码回填，启用/停用均需输入当前动态码确认。
- **WebAuthn**：绑定浏览器/设备的通行密钥后，可无需密码完成登录。登录强制要求用户验证（如指纹或 PIN）。

### 个人中心

在个人中心可维护账号资料：修改邮箱（用于头像与找回）、更换密码、管理 API 密钥、查看并注销本账号已登录的设备会话。列表展示每个会话的创建时间、最后活跃时间、IP 与设备标识，可对陌生会话单点吊销；也可一键退出全部设备。

头像来自 Cravatar：基于邮箱哈希，同一邮箱在不同站点间头像保持一致。

### 第三方应用授权

本站可作为 OAuth2.0 / OIDC 授权服务器。当第三方应用请求授权时，授权页会列出该应用申请的数据权限范围，并带有防重放参数（state / nonce）。支持授权码（含 PKCE）与设备授权（扫码/输入用户码）两种流程，签发与刷新令牌均做轮换，令牌只以哈希形式落库。

## 面向管理员

管理后台用于日常运营，入口在导航栏的「管理」区域。管理员可查看与检索用户列表，了解注册时间、IP、邮箱等资料。管理员仅能修改自己的账号信息，不能改其他管理员账户，也不能把普通用户提升为管理员。

访问控制遵循两级权限：

| 能力 | 普通用户 | 管理员 | 超管 |
| --- | :---: | :---: | :---: |
| 使用个人中心 | 是 | 是 | 是 |
| 管理用户列表 | — | 是 | 是 |
| 调整普通用户与管理员的权限组 | — | — | 是 |
| 修改站点配置 | — | — | 是 |
| 执行数据清理等危险操作 | — | — | 是 |
| 修改任意用户用户名 | — | — | 是 |

超管拥有全部权限，不能对其禁用或删除；超管可修改其他用户的用户名（须符合 4–16 位格式且不重名），但不会修改自己的权限组与状态。数据清理类危险接口仅超管可调，执行时会将全部八张表清空并退出所有账号、回到初始化状态，请谨慎操作。

## 常见问题

- **换了站点域名后 WebAuthn 用不了？** WebAuthn 凭据绑定 `config.json` 的 `webAuthn.rpID` 与 `expectedOrigin`，域名不一致会验证失败，且换域名需重新注册凭据。
- **进程重启后所有人都掉线了？** 会话存于内存，Nitro 进程重启即全部失效，属预期行为。
- **忘记部署时设置的会话密钥？** 更换 `NUXT_SESSION_PASSWORD` 会让全部会话 cookie 失效，用户需重新登录。
